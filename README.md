# RAG-System

## Architecture Overview

This project implements a Retrieval Augmented Generation (RAG) system with a Streamlit front-end, leveraging LangChain for orchestrating the RAG pipeline. It utilizes OpenAI embeddings served through OpenRouter for creating document embeddings and AWS RDS PostgreSQL with the `pgvector` extension for storing and retrieving these embeddings.

### Key Components:

1.  **Streamlit Application (`app.py`)**:
    *   **User Interface**: Provides a web interface for interacting with the RAG system.
    *   **Knowledge Base Manager**: A sidebar section that allows users to paste text chunks, which are then processed and added to the vector store.
    *   **Chat Interface**: The main section where users can input questions and receive answers generated by the LLM, augmented with retrieved context.

2.  **Environment Configuration**:
    *   Reads `DB_URI` (PostgreSQL connection string) and `OPENAI_API_KEY` from `.env` files or Streamlit secrets for secure credential management.

3.  **Embedding Model & Vector Store Initialization**:
    *   **OpenAIEmbeddings (via OpenRouter)**: Used to generate numerical vector representations (embeddings) of text documents. OpenRouter acts as a unified API gateway, allowing access to various LLMs and embedding models.
    *   **PGVector (AWS RDS PostgreSQL)**: A PostgreSQL database with the `pgvector` extension configured to store the generated text embeddings. This acts as the vector database for efficient similarity search. The `init_vector_store` function, decorated with `@st.cache_resource`, ensures that the vector store is initialized only once per session.

4.  **Text Splitter**:
    *   **RecursiveCharacterTextSplitter**: Breaks down large text documents into smaller, manageable chunks (e.g., 500 characters with 50-character overlap) suitable for embedding and retrieval. This is crucial for handling documents that exceed the embedding model's context window and for improving retrieval granularity.

5.  **Language Model (LLM)**:
    *   **ChatOpenAI (via OpenRouter)**: Utilizes a large language model (specifically `openai/gpt-4o-mini`) from OpenAI, accessed through the OpenRouter platform, to generate coherent and context-aware responses.

### Data Flow:

#### 1. Document Ingestion:

1.  **User Input**: A user pastes raw text into the "Knowledge Base Manager" text area in the Streamlit sidebar.
2.  **Text Splitting**: The input text is segmented into smaller `documents` (chunks) using `RecursiveCharacterTextSplitter`.
3.  **Embedding Generation**: Each document chunk is converted into a high-dimensional vector embedding using `OpenAIEmbeddings`.
4.  **Vector Storage**: The generated embeddings, along with their corresponding text content, are stored in the `PGVector` database (AWS RDS PostgreSQL).

#### 2. Query Processing (RAG Pipeline):

1.  **User Query**: A user enters a question into the "Ask Your Documents" text input field.
2.  **Relevant Document Retrieval**: The query is embedded using the same `OpenAIEmbeddings` model. This query embedding is then used to perform a similarity search against the `PGVector` database to retrieve the `k` (e.g., 3) most relevant document chunks.
3.  **Context Construction**: The retrieved document chunks are formatted and combined to form a contextual prompt for the LLM.
4.  **LLM Invocation**: The formatted prompt, including the original question and the retrieved context, is sent to the `ChatOpenAI` LLM (via OpenRouter).
5.  **Response Generation**: The LLM generates an answer based *only* on the provided context.
6.  **Display Results**: The generated answer is displayed to the user. Additionally, the retrieved context chunks are shown in an expandable section, allowing the user to verify the sources.

### Technologies Used:

*   **Python**: Primary programming language.
*   **Streamlit**: For building the interactive web application.
*   **LangChain**: Framework for developing applications powered by language models, used for orchestrating the RAG pipeline.
*   **dot_env**: For loading environment variables.
*   **OpenAIEmbeddings**: For generating text embeddings.
*   **OpenRouter**: A unified API for accessing various AI models, used here for both embeddings and the LLM.
*   **langchain_postgres (PGVector)**: LangChain integration for PostgreSQL with `pgvector` extension, serving as the vector store.
*   **AWS RDS PostgreSQL**: The managed relational database service storing the vector embeddings.
*   **ChatOpenAI**: The large language model used for generation.
*   **RecursiveCharacterTextSplitter**: For efficient document chunking.
